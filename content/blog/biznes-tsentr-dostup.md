Управляющая компания бизнес-центра сталкивается с задачей, которую стандартные СКУД не решают: **несколько организаций на одной территории с разными правилами для каждой**. Компания А работает с 8 до 20, компания Б — круглосуточно, у компании В — временные подрядчики каждую неделю. Карточки теряются, сотрудники уходят и их доступ надо срочно блокировать, а управляющая компания не должна знать кто именно работает у арендатора.

---

## Проблемы классического подхода

**Один СКУД на всех.**
Всех сотрудников всех арендаторов заводит один администратор управляющей компании. Он знает всё о всех, его нельзя ругать и нельзя уволить — без него система встаёт.

**Нет изоляции данных.**
HR компании А может случайно или специально увидеть список сотрудников компании Б. Это нарушение 152-ФЗ.

**Медленное отключение уволенных.**
Сотрудника уволили в пятницу вечером. Карточку заблокирует администратор СКУД в понедельник утром. 60 часов карточка работает.

**Нет временных пропусков.**
Курьер, сантехник, гость — каждому нужно пройти через охрану, заполнить бумажный журнал, получить гостевой бейдж. Очередь у стойки ресепшн.

## Архитектура мультиарендаторного доступа

TenantPass строится вокруг понятия **арендатор** (tenant): каждая организация — изолированное пространство.

```
Управляющая компания (platform_admin)
  ├── Видит: статистику по всем арендаторам, журнал общих зон
  ├── Управляет: общими зонами (парковка, лобби, конференц-залы)
  └── НЕ видит: кто именно работает у арендаторов

Арендатор А (tenant_admin)
  ├── Добавляет/удаляет своих сотрудников САМОСТОЯТЕЛЬНО
  ├── Настраивает расписание доступа для своей компании
  ├── Видит: только своих людей
  └── НЕ видит: арендатора Б
```

Управляющая компания **делегирует** управление арендаторам. Каждый управляет своим пространством сам.

## Как это работает на практике

### Новый сотрудник арендатора

1. HR арендатора открывает портал (веб или мобильное приложение)
2. Вводит данные нового сотрудника
3. Сотрудник получает QR-код на телефон или приходит на ресепшн за карточкой
4. С этого момента он может пройти в свою зону

**Время: 3 минуты. Управляющая компания не участвует.**

### Увольнение

1. HR нажимает «Заблокировать» в профиле сотрудника
2. Доступ заблокирован мгновенно
3. Карточку можно не забирать — она больше не работает

### Гость на один день

1. Сотрудник компании создаёт временный пропуск через приложение
2. Гость получает QR-код в мессенджере
3. Пропуск действует с 10:00 до 18:00 только в зону переговорных
4. После 18:00 — автоматически деактивируется

## Зонирование объекта

| Зона | Кто имеет доступ |
|------|-----------------|
| Парковка (въезд) | Все арендаторы по расписанию |
| Лобби + ресепшн | Все + гости с временным пропуском |
| Лифты | Все арендаторы (до своего этажа) |
| Этаж компании А | Только сотрудники компании А |
| Переговорные (общие) | По бронированию через систему |
| Серверная | Только IT-персонал, только в рабочее время |
| Технические зоны | Только сотрудники УК |

## Учёт рабочего времени для арендаторов

Арендаторы могут подключить модуль СУРВ:

- Табель строится автоматически по событиям прохода
- Выгрузка в 1С:ЗУП
- HR видит кто пришёл, кто опоздал, кто задержался
- Управляющая компания не имеет доступа к этим данным

## Выгода для арендаторов

Арендаторы получают **собственную систему контроля доступа** без капитальных вложений:
- Не надо покупать свой СКУД
- Управляют доступом самостоятельно
- Данные изолированы от других

Это конкурентное преимущество объекта на рынке аренды.
