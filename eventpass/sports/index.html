EventPass для спортивного события

EventPass для спортивного события

Задача

Спортивное мероприятие: футбольный матч, хоккей, боевые искусства, марафон, соревнования по единоборствам. Тысячи зрителей, строгое разделение на секторы, несколько категорий участников (атлеты, судьи, медики, пресса, VIP, фанаты).

Главная боль: поддельные билеты в VIP-секторе, фанаты с билетами другого сектора, атлеты не могут войти в технические зоны без долгих согласований.

Категории участников

Зрители:
  fan_standard    — обычный болельщик, конкретный сектор
  fan_vip         — VIP-зона / бизнес-трибуна
  fan_away        — гостевые фанаты (отдельный сектор, отдельный вход)
  
Официальные лица:
  athlete         — спортсмен, доступ к раздевалкам, полю
  coach           — тренер / тренерский штаб
  referee         — судья / арбитр
  medic           — медицинский персонал + поле
  
Медиа:
  press           — пресса, трибуна прессы
  photographer    — фотограф, зона press_pit у поля
  tv_crew         — телевизионная съёмочная группа
  
Персонал:
  staff_security  — охрана стадиона
  staff_steward   — стюарды (организаторы движения зрителей)
  staff_technical — технические службы
  vip_host        — хост VIP-зоны

Зоны

Стандартный стадион:

  public_entrance    — вход в периметр стадиона (все)
  sector_north       — северная трибуна
  sector_south       — южная трибуна (гостевые фанаты)
  sector_east        — восточная трибуна
  sector_west        — западная трибуна + VIP
  vip_lounge         — VIP-лаунж (бар, трансляция)
  press_tribune      — пресс-трибуна
  press_pit          — зона съёмки у поля
  mixed_zone         — зона общения атлетов с прессой
  tunnel_players     — тоннель игроков
  locker_room_home   — раздевалка хозяев
  locker_room_away   — раздевалка гостей
  field              — поле (атлеты + медики + судьи)
  technical_rooms    — технические помещения

Ключевые сценарии

Сценарий 1: Управление потоками зрителей

40 000 болельщиков, 12 входов:

EventPass отображает в реальном времени:
  Вход С1: 3 400 чел/час  ✅ зелёный
  Вход С2: 2 100 чел/час  ✅ зелёный
  Вход С3: 4 800 чел/час  🟡 жёлтый (>80% мощности)
  Вход Ю1: 5 200 чел/час  🔴 красный — очередь

Менеджер мероприятия:
  → Перенаправляет зрителей с ЮГА на СЕВЕР через Telegram-бот
  → Отправляет SMS держателям билетов Ю1-500: "Рекомендуем вход С3"

Сценарий 2: Раздельный вход гостевых фанатов

Гостевые фанаты:
  QR-код с меткой: sector=south, entrance=south_only

На северном входе:
  Болельщик "Спартака" пытается войти в северный вход
  → EventPass: ❌ deny — используйте южный вход
  → Экран: "Ваш вход: ЮЖНЫЕ ВОРОТА"
  → Охрана не спорит

Важно: физическое разделение потоков предотвращает конфликты.

Сценарий 3: Аккредитация атлетов

За сутки до матча:
  Команда передаёт список игроков (25 чел) через API
  Каждый получает цифровой пасс

На КПП команды:
  Автобус команды → охрана сканирует пассы
  → Все 25 игроков + 10 тренерского штаба
  → mixed_zone, locker_room_home, tunnel, field — открыты

За 2 часа до матча: атлет уходит за покупками:
  → Повторный вход по тому же пассу — работает

Сценарий 4: Экстренный медицинский доступ

Игрок получил травму на поле.

Медик с браслетом или QR-пассом:
  → Уже аккредитован: field, locker_room, tunnel → всегда работает

Внешняя бригада скорой:
  → Охрана при входе в режиме "Экстренный доступ" (один нажим)
  → Все ворота, ведущие к полю, разблокируются для бригады
  → Лог: "Emergency access granted, 14:23:07"

Сценарий 5: Марафон / забег

Другой формат: 2 000 участников, старт-финиш, промежуточные пункты

Участники:
  → QR-код или RFID-чип на номере
  → На старте: отметка в системе
  → На промежуточных КП: автоматическая отметка (считыватель у ворот)
  → На финише: время финиша, место, диплом

Организатор видит в реальном времени:
  Стартовало: 1 987 / 2 000
  На трассе: 1 412
  Финишировало: 575
  Сошли: 12 (отметились на КП выхода)
  Не финишировали и не сошли: 3 (поиск)

Интеграция с СКУД стадиона

Крупные стадионы имеют собственные турникеты (Perco, HID, Lenel).

EventPass как слой поверх:
  Вариант А: EventPass → API стадионного СКУД (push разрешений)
    Плюс: используют своё железо
    Минус: зависимость от API стадиона

  Вариант Б: EventPass считыватели параллельно (overlay)
    Турникет стадиона остаётся
    EventPass-планшет рядом — только для проверки (без управления замком)
    Плюс: никакой интеграции
    Минус: двойная проверка (неудобно)

  Вариант В: Замена на EventPass-совместимые считыватели
    Долгосрочно для стадиона-партнёра
    Полный контроль

Аналитика для организатора

После матча:
  Явка по секторам: факт vs план (% заполнения)
  Динамика прихода: за 2 часа до, за 1 час, опоздавшие
  Средняя скорость сканирования по входам
  Инциденты (неверные зоны, поддельные билеты): N случаев
  VIP-явка: 95%, fan_away: 87%, press: 62%

Для безопасности:
  Топ-3 входа по нарушениям
  Время пиковой нагрузки
  Время полного заполнения стадиона
