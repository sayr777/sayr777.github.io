Отказоустойчивость HomePass (замечания 4+5+6)

Отказоустойчивость HomePass (замечания 4+5+6)

DIY-минималистичный подход: никаких облаков, максимум самодельного

Принцип: HA управляет, но не является точкой отказа

Критические системы (котёл, замки, пожарная сигнализация) работают без HA. HA добавляет удобство и аналитику, но не является условием работы.

Замечание 4: HA как SPOF — котёл и замки

Котёл — автономная термостатная логика

# esphome/boiler-controller.yaml
# ESP32 рядом с котлом — работает полностью автономно

sensor:
  - platform: dallas_temp
    address: 0x1c3c01d6076bf128
    name: "Температура улица"
    id: outdoor_temp

  - platform: dallas_temp
    address: 0xf83c01d607923c28
    name: "Температура дом"
    id: indoor_temp

switch:
  - platform: gpio
    name: "Котёл — запуск горелки"
    id: boiler_relay
    pin: GPIO26

# Локальный термостат: работает без HA
# Если HA недоступен — котёл всё равно греет по setpoint
thermostat:
  - platform: pid
    name: "Термостат котла"
    sensor: indoor_temp
    default_target_temperature: 21
    cool:
      - switch.turn_off: boiler_relay
    heat:
      - switch.turn_on: boiler_relay
    control_parameters:
      kp: 0.3
      ki: 0.001
      kd: 0.0

# Аппаратный watchdog: если ESP32 завис — перезагрузится сам
esphome:
  on_boot:
    priority: 600
    then:
      - lambda: |-
          esp_task_wdt_init(30, true);  // 30 сек watchdog, panic=true
          esp_task_wdt_add(NULL);

Замки — failsafe без HA

# Все замки используют fail-safe политику самого устройства (не HA)
# Электрозащёлки: fail-open (нет питания = открыто)
# Для каждого ESP32-контроллера двери: локальная кнопка выхода работает всегда

# esphome/door-entrance.yaml
binary_sensor:
  - platform: gpio
    name: "Кнопка выхода"
    pin:
      number: GPIO19
      mode: INPUT_PULLUP
      inverted: true
    on_press:
      # Работает без HA — напрямую через ESPHome
      - switch.turn_on: door_lock_relay
      - delay: 5s
      - switch.turn_off: door_lock_relay

HA сервер: watchdog и питание

DIY UPS на ESP32 (без покупного ИБП)

Схема DIY UPS для Raspberry Pi / мини-ПК (5В):
  220В → TP4056 зарядное → Li-Ion 18650 × 2 (последовательно = 8.4В)
  → MP1584 step-down 8.4В→5В → Raspberry Pi
  
При пропадании 220В: батарея берёт нагрузку автоматически
Ёмкость 2×3000 мАч = 6000 мАч → RPi4 (~3Вт) ≈ 8 часов

Мониторинг батареи: ESP32 ADC → HA sensor.ups_voltage

# esphome/ups-monitor.yaml
sensor:
  - platform: adc
    pin: GPIO34
    name: "UPS — напряжение батареи"
    id: ups_voltage
    filters:
      - multiply: 3.3   # делитель напряжения 1:3
    unit_of_measurement: V
    attenuation: 11db

binary_sensor:
  - platform: gpio
    name: "UPS — сеть 220В"
    pin: GPIO35
    device_class: power

# HA automation
# - alias: "UPS: низкий заряд"
#   trigger: numeric_state entity_id: sensor.ups_voltage below: 6.8
#   action: notify + graceful shutdown

# Все конфиги хранятся в /config/esphome/*.yaml

#   boiler-controller.yaml
#   door-entrance.yaml
#   temp-sensors.yaml
#   ...
#   secrets.yaml     ← пароли, не в git

Групповое обновление скриптом

#!/bin/bash
# update-all-esphome.sh — обновить все устройства
# Запускать из /config/esphome/

DEVICES=(
  boiler-controller
  door-entrance
  door-garage
  temp-sensors
  motion-living-room
  energy-meter
)

for device in "${DEVICES[@]}"; do
  echo "=== Updating: $device ==="
  esphome run "${device}.yaml" --device "api"   # OTA через API
  sleep 10   # дать устройству перезагрузиться
done

# Версионирование прошивок в YAML
# esphome/_version.yaml — общий для всех устройств
substitutions:
  fw_version: "2026.10.1"

# Каждое устройство импортирует:
# packages:
#   version: !include _version.yaml

Замечание 6: топология сети — DIY минимализм

Правило: один протокол = одна задача

WiFi (2.4 ГГц):    → ESPHome устройства с реле (питание от сети, не батарейки)
Zigbee:            → Батарейные датчики (движение, температура, открытие)
BLE (ESPresense):  → Определение чьего телефона в комнате
Проводной PoE:     → IP-камеры (надёжнее WiFi)

Z-Wave не используем — дорого, сложно, не нужно для DIY.

Размещение точек доступа OpenWrt

Дом 150–200 м² (одноэтажный):
  1 роутер-AP в центре = достаточно
  
Дом 200–300 м² (двухэтажный):
  1 роутер (роль: шлюз + DHCP) в щитке
  1 AP (роль: только WiFi) на 2 этаже
  → Соединение: витая пара Cat5e через стену
  → OpenWrt WDS или 802.11r Fast BSS Transition

Zigbee: координатор (CC2531 или Sonoff Zigbee 3.0 USB)
  → разместить в центре дома (USB-удлинитель 2-3 м от RPi)
  → Zigbee-розетки Sonoff S26 = повторители сети (бесплатно)
  → Цель: дотянуться до самого дальнего датчика ≤ 2 хопа

Разделение каналов 2.4 ГГц

WiFi роутер:   канал 1 (2412 МГц)
Zigbee:        канал 11 (2462 МГц, соответствует Zigbee канал 11)
  → НЕ совпадают, интерференция минимальна

BLE:           использует frequency hopping, специальной настройки не требует

Если сосед на канале 1 — переключить WiFi на канал 6 или 13.

Сегменты VLAN (упрощённая схема HomePass)

VLAN 1  — семья (основные устройства)
VLAN 10 — IoT (ESPHome, Zigbee2MQTT — нет выхода в интернет, только к HA)
VLAN 20 — гости (только интернет, изолированы)
VLAN 30 — камеры (только к Frigate, никуда больше)

# OpenWrt UCI — IoT VLAN без интернета
uci set network.iot=interface
uci set network.iot.type=bridge
uci set network.iot.ifname=eth0.10
uci set network.iot.proto=static
uci set network.iot.ipaddr=192.168.10.1
uci set network.iot.netmask=255.255.255.0

# Правило: IoT не может выходить в WAN
iptables -I FORWARD -i br-iot -o eth0.1 -j DROP        # нет к основной сети
iptables -I FORWARD -i br-iot -o wan -j DROP            # нет в интернет
iptables -A FORWARD -i br-iot -d 192.168.1.0/24 -j ACCEPT  # к HA разрешено
