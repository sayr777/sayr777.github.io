Liquidsoap — планировщик потоков

Liquidsoap — язык программирования и рантайм для управления аудиопотоками. Всё что угодно: расписание, jingle’ы, кроссфейды, ducking при объявлениях.

Установка

# Ubuntu / Debian
apt-get install liquidsoap liquidsoap-plugin-all

# Или через opam (последняя версия)
opam install liquidsoap

Базовый скрипт: два плейлиста по расписанию + ducking

# /etc/liquidsoap/zones.liq

# === ИСТОЧНИКИ ===

# Утренняя подборка (спокойная)
morning = playlist(
  mode = "randomize",
  "/var/music/morning/"
)

# Дневная (активная)
daytime = playlist(
  mode = "randomize",
  "/var/music/daytime/"
)

# Вечерняя (расслабляющая)
evening = playlist(
  mode = "randomize",
  "/var/music/evening/"
)

# Интернет-радио как фолбэк
fallback_radio = mksafe(
  input.http("http://radiorecord.ru/mp3/rr_320")
)

# === РАСПИСАНИЕ ===

music = switch(
  track_sensitive = false,
  [
    ({ 07h00m - 11h00m }, morning),
    ({ 11h00m - 18h00m }, daytime),
    ({ 18h00m - 23h00m }, evening),
    ({ true },             fallback_radio)   # ночью — радио
  ]
)

# Кроссфейд между треками (3 секунды)
music = crossfade(duration = 3.0, music)

# === ОБЪЯВЛЕНИЯ (Ducking) ===

# Asterisk пишет в этот файл сигнал "объявление активно"
announce_active = ref(false)

# Duck: при объявлении музыка тихнет до 20% за 1 сек
music_ducked = amplify(
  override = "liq_amplify",
  music
)

on_metadata(
  fun(m) ->
    if !announce_active then
      music_ducked.set("liq_amplify", lin_of_dB(-14.0))  # -14 dB
    end,
  music
)

# HTTP endpoint для управления ducking из Asterisk/HA
harbor.http.register(
  port = 8005,
  method = "POST",
  "/duck",
  fun(_, response) ->
    begin
      announce_active := true
      music_ducked.set("liq_amplify", lin_of_dB(-14.0))
      response.status_code(200)
      response.data("ducking on")
    end
)

harbor.http.register(
  port = 8005,
  method = "POST",
  "/unduck",
  fun(_, response) ->
    begin
      announce_active := false
      music_ducked.set("liq_amplify", lin_of_dB(0.0))
      response.status_code(200)
      response.data("ducking off")
    end
)

# === ЗОНЫ — разные потоки на Icecast ===

# Зона А — лобби (громче, более энергичная)
zone_a = amplify(1.2, music_ducked)

# Зона Б — рабочее пространство (тише)
zone_b = amplify(0.7, music_ducked)

# Улица — отдельный плейлист, только летом
outdoor_music = playlist("/var/music/outdoor/")
zone_outdoor = switch([
  ({ 05h00m - 23h00m }, amplify(1.5, outdoor_music)),
  ({ true }, blank())           # ночью тишина
])

# === ВЫВОД НА ICECAST ===

output.icecast(
  %mp3(bitrate = 128),
  host = "localhost", port = 8000,
  password = "icecast_source_pass",
  mount = "/zone-a",
  name = "Zone A — Lobby",
  zone_a
)

output.icecast(
  %mp3(bitrate = 96),
  host = "localhost", port = 8000,
  password = "icecast_source_pass",
  mount = "/zone-b",
  name = "Zone B — Workspace",
  zone_b
)

output.icecast(
  %mp3(bitrate = 128),
  host = "localhost", port = 8000,
  password = "icecast_source_pass",
  mount = "/outdoor",
  name = "Outdoor",
  zone_outdoor
)

Icecast2 — стриминг-сервер

<!-- /etc/icecast2/icecast.xml -->
<icecast>
  <location>Moscow</location>
  <admin>admin@company.ru</admin>

  <limits>
    <clients>100</clients>
    <sources>10</sources>
    <burst-size>65536</burst-size>
  </limits>

  <authentication>
    <source-password>icecast_source_pass</source-password>
    <relay-password>icecast_relay_pass</relay-password>
    <admin-user>admin</admin-user>
    <admin-password>icecast_admin_pass</admin-password>
  </authentication>

  <hostname>192.168.1.X</hostname>

  <listen-socket>
    <port>8000</port>
    <bind-address>0.0.0.0</bind-address>
  </listen-socket>

  <!-- Только внутренняя сеть -->
  <security>
    <chroot>0</chroot>
  </security>

  <paths>
    <logdir>/var/log/icecast2</logdir>
    <webroot>/usr/share/icecast2/web</webroot>
  </paths>
</icecast>

Snapcast — синхронное мультизональное воспроизведение

Snapcast решает проблему рассинхронизации: все зоны играют одновременно с точностью до миллисекунды. Это важно в больших пространствах, где слышно несколько зон сразу.

graph LR LIQ["Liquidsoap\npipe output"] --> SNAP_SRV["Snapserver\n(на сервере)"] SNAP_SRV -->|TCP sync| C1["Snapclient\nЗона А (RPi Zero)"] SNAP_SRV -->|TCP sync| C2["Snapclient\nЗона Б (ESP32-A1S)"] SNAP_SRV -->|TCP sync| C3["Snapclient\nУлица (RPi Zero)"] SNAP_SRV -->|TCP sync| C4["Snapclient\nБаня (RPi Zero)"]

Сервер

apt-get install snapserver

# /etc/snapserver.conf
[stream]
source = pipe:///tmp/snapcast_pipe?name=main&sampleformat=48000:16:2

[http]
enabled = true
port = 1780         # веб-интерфейс управления

# Liquidsoap: дополнительный вывод в Snapcast pipe
output.file(
  %wav(channels=2, samplerate=48000, header=false),
  "/tmp/snapcast_pipe",
  music_ducked
)

Клиент (Raspberry Pi Zero 2W)

apt-get install snapclient

# /etc/default/snapclient
SNAPCLIENT_OPTS="--host 192.168.1.X --port 1704 --soundcard default"

# Задержка клиента (компенсация задержки усилителя)
snapclientctl latency 50   # мс

DIY клиент на ESP32-A1S (Lyrat Mini)

ESP32-A1S + ES8388 codec → I2S → усилитель → динамики
Прошивка: esp-idf + snapcast-esp32 (open-source)
Стоимость: ~1 500 ₽
Питание: 5V USB или PoE-сплиттер

Ducking — приглушение при объявлении

При поступлении PA-объявления из Asterisk или TTS из Home Assistant музыка автоматически приглушается.

sequenceDiagram participant HA as Home Assistant participant LIQ as Liquidsoap participant AST as Asterisk participant SNAP as Snapcast participant SPK as Динамики HA->>LIQ: POST /duck (музыка -14 dB за 1 сек) HA->>AST: AMI Originate → PA-объявление AST->>SNAP: SIP PA channel → audio note over SPK: Объявление хорошо слышно на фоне тихой музыки AST->>HA: AMI Event: Hangup HA->>LIQ: POST /unduck (музыка +14 dB за 2 сек)
# HA automation: ducking при объявлении
- alias: "PA объявление: приглушить музыку"
  trigger:
    - platform: webhook
      webhook_id: pa_announce_start
  action:
    - service: rest_command.liquidsoap_duck
      data: {}

- alias: "PA объявление: восстановить музыку"
  trigger:
    - platform: webhook
      webhook_id: pa_announce_end
  action:
    - delay: "00:00:02"   # пауза после объявления
    - service: rest_command.liquidsoap_unduck
      data: {}

# configuration.yaml — rest_command для Liquidsoap
rest_command:
  liquidsoap_duck:
    url: "http://192.168.1.X:8005/duck"
    method: POST
  liquidsoap_unduck:
    url: "http://192.168.1.X:8005/unduck"
    method: POST

Asterisk MOH (Music on Hold) — музыка при ожидании

Стандартный Music on Hold в Asterisk — тоже слушает Icecast-поток.

; /etc/asterisk/musiconhold.conf
[default]
mode=stream
directory=http://192.168.1.X:8000/zone-a   ; поток Icecast

; Отдельный класс для VIP-зоны (другая музыка)
[vip-lounge]
mode=stream
directory=http://192.168.1.X:8000/zone-b

Применение по проектам

TenantPass (офис/объект)

Расписание:
  08:00–09:00  Утренняя энергичная → рабочий настрой
  09:00–12:00  Фоновая инструментальная → концентрация
  12:00–13:00  Обеденная (чуть активнее)
  13:00–18:00  Фоновая инструментальная
  18:00+        Тихо / выключить

Зоны:
  Лобби / ресепшн     → zone-a (энергичнее, громче)
  Переговорные        → тишина (выключать при встрече через HA)
  Open space          → zone-b (тихо, не отвлекает)
  Столовая            → zone-c (общий фон)

HomePass (частный дом)

Расписание:
  07:00–09:00  Утренняя классика / джаз
  09:00–22:00  По желанию (голосовая команда)
  22:00+        Выключить везде

Зоны + управление голосом:
  "Включи музыку на кухне"    → zone-kitchen включить
  "Выключи везде"             → all zones off
  "Что-нибудь потише"         → amplify -3 dB текущая зона
  "Включи радио в бане"       → zone-sauna = radio stream

Баня: отдельный Snapcast-клиент, водозащищённый корпус
Улица: только летом (05:00–23:00), приглушается при закрытых воротах

EventPass (мероприятие)

Pre-event (двери открыты, гости входят):
  Энергичная музыка → создать атмосферу
  Громкость: 70%

Event (шоу идёт):
  Музыка выключена / только в фойе

Break / пауза:
  Фоновая музыка во всех зонах

Post-event (выход гостей):
  Расслабляющая музыка → плавное завершение

Управление: организатор через веб-панель EventPass
  → REST → Liquidsoap HTTP API → мгновенное переключение

      - icecast

      - ./snapserver.conf:/etc/snapserver.conf
      - /tmp/snapcast_pipe:/tmp/snapcast_pipe
    depends_on:
      - liquidsoap
