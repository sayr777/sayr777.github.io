Lago AGPL + коммерческое использование SaaS

Проблема

Lago — AGPL-3.0. При использовании в SaaS (TenantPass/EventPass продаётся клиентам через сеть) AGPL обязывает открыть исходники всего приложения, которое взаимодействует с Lago через сеть.

Три варианта решения

graph TD PROBLEM["Lago AGPL в SaaS — риск открытия исходников"] PROBLEM --> OPT1["Вариант 1: Lago Cloud\nКоммерческая лицензия\n~$500/мес"] PROBLEM --> OPT2["Вариант 2: Изоляция Lago\nОтдельный сервис с API-границей\nISOLATED: нет связи с бизнес-кодом"] PROBLEM --> OPT3["Вариант 3: Замена на Apache 2.0\nOpenMeter / custom"] OPT1 -->|рекомендуется для Enterprise| DONE1["✅ Нет рисков"] OPT2 -->|рекомендуется для MVP| DONE2["✅ AGPL распространяется только на изолированный сервис"] OPT3 -->|для self-hosted| DONE3["✅ Полная свобода"]

Вариант 2: Изоляция Lago (рекомендуется для старта)

AGPL требует открыть исходники программы, которая включает или линкует AGPL-код. Если Lago — это отдельный сервис, с которым взаимодействуете только через REST API, то ваш код не является производным произведением.

Архитектурная граница (AGPL firewall):

  [TenantPass API]  ──HTTP REST──→  [Lago Billing Service]
       ^                                      |
       |                           (только этот сервис AGPL)
  Ваш проприетарный код           (изолирован в Docker, нет общего кода)

  Правило:
  - Ваш код НЕ импортирует Lago библиотеки
  - Ваш код взаимодействует только через HTTP API
  - Lago запускается в отдельном Docker-контейнере
  - → ваш код НЕ является derivative work

# billing/lago_client.py — только HTTP, никакого import lago
import httpx
from typing import Optional

class BillingService:
    """Тонкий HTTP-клиент к Lago. Наш код не знает про AGPL внутренности."""

    def __init__(self, base_url: str, api_key: str):
        self.base = base_url
        self.headers = {"Authorization": f"Bearer {api_key}"}

    async def report_usage(self, tenant_id: str, metric: str, value: float,
                           transaction_id: Optional[str] = None):
        async with httpx.AsyncClient() as c:
            await c.post(f"{self.base}/api/v1/events", headers=self.headers, json={
                "event": {
                    "transaction_id": transaction_id or f"{tenant_id}-{metric}-{int(time())}",
                    "external_customer_id": tenant_id,
                    "code": metric,
                    "properties": {"value": value}
                }
            })

    async def get_invoice(self, tenant_id: str, period: str) -> dict:
        async with httpx.AsyncClient() as c:
            r = await c.get(f"{self.base}/api/v1/invoices",
                            headers=self.headers,
                            params={"external_customer_id": tenant_id, "period": period})
            return r.json()

Вариант 3: Замена Lago на OpenMeter (Apache 2.0)

OpenMeter — usage-based billing engine, Apache 2.0, нет AGPL рисков.

# docker-compose.openmeter.yml
services:
  openmeter:
    image: ghcr.io/openmeterio/openmeter:latest
    environment:
      POSTGRES_URL: postgresql://...
    ports:
      - "8888:8888"

# OpenMeter API почти идентичен Lago
import httpx

async def report_usage(customer_id: str, meter: str, value: float):
    async with httpx.AsyncClient() as c:
        await c.post("http://openmeter:8888/api/v1/events",
                     json={
                         "specversion": "1.0",
                         "type": f"com.tenantpass.{meter}",
                         "source": "api",
                         "subject": customer_id,
                         "data": {"value": value}
                     })
