Сетевой контроль доступа (NAC)

Сетевой контроль доступа (NAC)

Применяется во всех проектах: TenantPass, HomePass, EventPass

Пользователь подключается к WiFi или проводному порту → система идентифицирует его → автоматически помещает в нужный VLAN с соответствующими правами доступа к внутренним ресурсам и/или интернету.

FreeRADIUS — конфигурация

Установка

# Ubuntu 22.04
apt-get install freeradius freeradius-ldap freeradius-rest

# Конфиги
/etc/freeradius/3.0/
  clients.conf       # коммутаторы/AP (shared secret)
  users              # статические пользователи (тест)
  mods-enabled/
    ldap             # интеграция с Keycloak/LDAP
    rest             # интеграция с REST API
  sites-enabled/
    default          # основной virtual server
    inner-tunnel     # для PEAP/TTLS

clients.conf — регистрация коммутаторов и AP

# /etc/freeradius/3.0/clients.conf

# Managed switch (Cisco / MikroTik / UniFi)
client switch-floor1 {
    ipaddr          = 192.168.1.10
    secret          = VeryStr0ngSharedSecret!
    shortname       = switch-floor1
    nas_type        = cisco
}

client unifi-ap-office {
    ipaddr          = 192.168.1.11
    secret          = VeryStr0ngSharedSecret!
    shortname       = ap-office
}

# Подсеть для всех UniFi AP
client unifi-subnet {
    ipaddr          = 192.168.1.0/24
    secret          = VeryStr0ngSharedSecret!
}

Интеграция с Keycloak через LDAP

Keycloak умеет выступать LDAP-провайдером для FreeRADIUS.

# /etc/freeradius/3.0/mods-available/ldap

ldap {
    server      = "192.168.1.X"      # Keycloak host
    port        = 389                 # или 636 для TLS
    identity    = "cn=radius,dc=company,dc=ru"
    password    = "radius_bind_pass"
    base_dn     = "dc=company,dc=ru"

    user {
        base_dn       = "ou=users,${..base_dn}"
        filter        = "(uid=%{%{Stripped-User-Name}:-%{User-Name}})"
        # Получаем атрибуты для VLAN
        get_attribute_defaults = yes
    }

    group {
        base_dn   = "ou=groups,${..base_dn}"
        filter    = "(member=%{control:Ldap-UserDN})"
        name_attribute = cn
    }

    # Маппинг LDAP-групп → RADIUS-атрибуты VLAN
    update {
        control:Tunnel-Type            := VLAN
        control:Tunnel-Medium-Type     := IEEE-802
        control:Tunnel-Private-Group-ID:= "%{LDAP-Group:employees:20}"
    }
}

Динамический VLAN через unlang (политика)

# /etc/freeradius/3.0/sites-enabled/default
# В секции authorize:

authorize {
    filter_username
    preprocess
    
    # 802.1X: проверяем пользователя
    ldap
    if (LDAP-Group == "employees") {
        update reply {
            Tunnel-Type            = VLAN
            Tunnel-Medium-Type     = IEEE-802
            Tunnel-Private-Group-ID = 20    # Corporate VLAN
        }
    }
    elsif (LDAP-Group == "contractors") {
        update reply {
            Tunnel-Type            = VLAN
            Tunnel-Medium-Type     = IEEE-802
            Tunnel-Private-Group-ID = 40    # Contractor VLAN
        }
    }
    elsif (LDAP-Group == "security_officers") {
        update reply {
            Tunnel-Type            = VLAN
            Tunnel-Medium-Type     = IEEE-802
            Tunnel-Private-Group-ID = 20    # Corporate VLAN
            # + можно добавить bandwidth policy
        }
    }
    else {
        # Неизвестный пользователь → Quarantine
        update reply {
            Tunnel-Type            = VLAN
            Tunnel-Medium-Type     = IEEE-802
            Tunnel-Private-Group-ID = 99
        }
    }
    
    pap
}

Интеграция с Keycloak через REST (альтернатива LDAP)

# /etc/freeradius/3.0/mods-available/rest

rest {
    connect_uri = "http://192.168.1.X:8080"

    authorize {
        uri  = "${..connect_uri}/realms/tenantpass/protocol/openid-connect/token/introspect"
        method = "POST"
        body = "token=%{User-Password}&token_type_hint=access_token"
        tls = ${..tls}
    }
}

MikroTik (RouterOS)

/interface vlan
add interface=bridge name=vlan-corporate vlan-id=20
add interface=bridge name=vlan-contractor vlan-id=40
add interface=bridge name=vlan-guest vlan-id=50
add interface=bridge name=vlan-iot vlan-id=60

# RADIUS-сервер
/radius
add address=192.168.1.X secret=VeryStr0ngSharedSecret! service=dot1x

# 802.1X на портах
/interface dot1x server
add interface=ether2 auth-types=dot1x mac-auth=yes \
    radius-mac-format=XX-XX-XX-XX-XX-XX
add interface=ether3 auth-types=dot1x mac-auth=yes
add interface=ether4 auth-types=dot1x mac-auth=yes

# Guest VLAN при неудаче аутентификации
/interface dot1x server
set [find interface=ether2] guest-vlan-id=50

Cisco IOS (классика)

! RADIUS
radius server FreeRADIUS
  address ipv4 192.168.1.X auth-port 1812 acct-port 1813
  key VeryStr0ngSharedSecret!

! AAA
aaa new-model
aaa authentication dot1x default group radius
aaa authorization network default group radius

! Включить 802.1X глобально
dot1x system-auth-control

! На порту

  dot1x auth-fail vlan 99   ! VLAN при провале
  spanning-tree portfast

Captive Portal — гостевой доступ

Для устройств без 802.1X-клиента (телефоны гостей, IoT).

Вариант 1: pfSense + FreeRADIUS Captive Portal

pfSense → Services → Captive Portal → Add Zone:
  Interface: VLAN 50 (guest)
  Authentication: RADIUS
  RADIUS Server: 192.168.1.X
  
  Vouchers: включить (для EventPass — одноразовые коды)
  или: Local Users (для HomePass — просто пароль "гость")
  или: RADIUS MAC auth (для IoT)

Вариант 2: Keycloak как Captive Portal

sequenceDiagram participant G as Гость (телефон) participant FW as pfSense / OPNsense participant KC as Keycloak G->>FW: HTTP запрос (любой сайт) FW->>G: Redirect → https://keycloak/captive?redirect=... G->>KC: Открывает страницу входа G->>KC: Вводит имя + телефон (или QR EventPass) KC->>KC: Создаёт сессию + RADIUS CoA KC->>FW: RADIUS Change-of-Authorization (разрешить) FW->>G: Redirect → исходный сайт G->>FW: Теперь трафик разрешён (VLAN Guest)

Вариант 3: EventPass QR → WiFi-доступ

Участник мероприятия:
  1. Подключается к WiFi "EventPass-Guest" (открытая сеть)
  2. Браузер открывает Captive Portal → страница EventPass
  3. Участник сканирует свой QR или вводит код с билета
  4. EventPass API → pfSense CoA → разрешить интернет
  5. Участник получает доступ до конца мероприятия

Реализация (EventPass API):
  POST /api/v1/events/{event_id}/wifi-auth
  {
    "qr_token": "ep_abc123",
    "mac_address": "AA:BB:CC:DD:EE:FF"
  }
  → RADIUS CoA к pfSense: разрешить MAC → VLAN 40

Контроль ресурсов по VLAN (Firewall rules)

pfSense / OPNsense — правила между VLAN

# VLAN Corporate (20) → разрешить всё
pass out on VLAN20 all

# VLAN Contractor (40) → только whitelist сервисов
pass in  on VLAN40 proto tcp to 192.168.1.100 port 443  # только ERP
pass in  on VLAN40 proto tcp to 192.168.1.101 port 443  # только 1С
block in on VLAN40 all                                   # остальное запрещено

# VLAN Guest (50) → только интернет, запретить LAN
block in  on VLAN50 to 192.168.0.0/16    # запретить доступ к внутренней сети
pass  out on VLAN50 proto tcp to any port {80, 443}      # интернет
pass  out on VLAN50 proto udp to any port 53             # DNS

# VLAN IoT (60) → только к Home Assistant / Keycloak
pass in on VLAN60 proto tcp to 192.168.1.50 port 8123   # HA
pass in on VLAN60 proto tcp to 192.168.1.X  port 8080   # Keycloak
block in on VLAN60 all

Ограничение полосы пропускания (EventPass гости)

# pfSense → Firewall → Traffic Shaper → Limiters
# Лимит для VLAN Attendees: 5 Мбит/с на пользователя

# OPNsense → Traffic Shaper → Pipes:
  Pipe "guest-down": 5000 Kbit/s
  Pipe "guest-up":   2000 Kbit/s

# Правило для VLAN 40:
  pass in on VLAN40 all pipe guest-up
  pass out on VLAN40 all pipe guest-down

MAC-аутентификация для IoT

Устройства без 802.1X (ESP32, камеры, датчики) — аутентифицируются по MAC-адресу.

FreeRADIUS — MAB (MAC Authentication Bypass):

# /etc/freeradius/3.0/mods-enabled/files
users:
  # Камера Frigate
  "AA-BB-CC-DD-EE-01" Cleartext-Password := "AA-BB-CC-DD-EE-01"
      Tunnel-Type = VLAN,
      Tunnel-Medium-Type = IEEE-802,
      Tunnel-Private-Group-ID = 60    # IoT VLAN

  # ESP32 датчик
  "AA-BB-CC-DD-EE-02" Cleartext-Password := "AA-BB-CC-DD-EE-02"
      Tunnel-Type = VLAN,
      Tunnel-Medium-Type = IEEE-802,
      Tunnel-Private-Group-ID = 60

  # Неизвестное устройство — Quarantine
  DEFAULT
      Tunnel-Type = VLAN,
      Tunnel-Medium-Type = IEEE-802,
      Tunnel-Private-Group-ID = 99

При увольнении сотрудника — немедленный отзыв сетевого доступа:

sequenceDiagram participant ADMIN as tenant_admin participant KC as Keycloak participant TP as TenantPass API participant RAD as FreeRADIUS participant SW as Коммутатор ADMIN->>KC: Деактивировать пользователя KC->>TP: Webhook: user.disabled TP->>RAD: Disconnect-Request (CoA)\nUser-Name=ivanov RAD->>SW: RADIUS Disconnect-Request SW->>SW: Принудительно завершить сессию порта SW-->>RAD: Disconnect-ACK note over SW: Порт → Quarantine VLAN 99\nдо повторной аутентификации

RADIUS CoA (Change of Authorization) из кода

import socket, struct

def radius_coa_disconnect(nas_ip: str, shared_secret: bytes, username: str):
    """Отправить CoA Disconnect-Request на коммутатор"""
    # Формирование RADIUS Disconnect-Request (код 40)
    # ... (требует реализации или библиотеки pyrad)
    
    from pyrad.client import Client
    from pyrad.dictionary import Dictionary
    import pyrad.packet

    client = Client(
        server=nas_ip,
        coaport=3799,
        secret=shared_secret,
        dict=Dictionary("dictionary")
    )
    request = client.CreateCoAPacket(
        code=pyrad.packet.DisconnectRequest
    )
    request["User-Name"] = username
    reply = client.SendPacket(request)
    return reply.code == pyrad.packet.DisconnectACK
