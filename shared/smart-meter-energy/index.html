PZEM-004T v3 — самый дешёвый вариант

Модуль измеряет: напряжение, ток, мощность, энергию, частоту, cos φ. Точность ±0.5%.

Схема подключения

Однофазная сеть (220В):
  L (фаза) → PZEM-004T → нагрузка
  N (ноль) → PZEM-004T → нагрузка

  PZEM UART:
    TX → ESP32 GPIO16 (RX2)
    RX → ESP32 GPIO17 (TX2)
    VCC → 5В
    GND → GND

  ⚠ Гальваническая развязка обязательна при работе со 220В!
     Используйте оптопару или готовый PZEM с изолированным UART.

# esphome/energy-meter.yaml

    voltage:

      unit_of_measurement: V
    energy:
      name: "Потребление"
      unit_of_measurement: kWh
      device_class: energy
      state_class: total_increasing   # для HA Energy Dashboard

      name: "Мощность"

      unit_of_measurement: Hz

      name: "Коэффициент мощности"
    update_interval: 10s
    uart_id: pzem_uart

SDM630 — трёхфазный профессиональный

Для TenantPass (офис/объект) и стройплощадки. Din-рейка, RS-485 Modbus RTU.

# esphome/energy-meter-3phase.yaml
modbus:
  id: modbus1
  uart_id: modbus_uart

modbus_controller:
  - id: sdm630
    address: 0x01
    modbus_id: modbus1
    update_interval: 30s

sensor:
  # Трёхфазные значения
  - platform: modbus_controller
    modbus_controller_id: sdm630
    name: "Фаза A — напряжение"
    address: 0x0000
    register_type: holding
    value_type: FP32
    unit_of_measurement: V
    accuracy_decimals: 1

  - platform: modbus_controller
    modbus_controller_id: sdm630
    name: "Фаза A — ток"
    address: 0x0006
    register_type: holding
    value_type: FP32
    unit_of_measurement: A

  - platform: modbus_controller
    modbus_controller_id: sdm630
    name: "Мощность суммарная"
    address: 0x0034
    register_type: holding
    value_type: FP32
    unit_of_measurement: W
    device_class: power

  - platform: modbus_controller

Меркурий 206 / 230 — российский счётчик

Широко распространён в России. Протокол — собственный поверх RS-485 (Mercury protocol), или CAN. Есть библиотеки для ESPHome и HA.

Вариант A: ESPHome + кастомный компонент

# esphome/mercury-206.yaml
# Используем внешний компонент для протокола Меркурий

external_components:
  - source:
      type: git
      url: https://github.com/custom-components/esphome-mercury-energy-meter
    components: [mercury_energy_meter]

uart:
  id: mercury_uart
  baud_rate: 9600
  tx_pin: GPIO17
  rx_pin: GPIO16

sensor:
  - platform: mercury_energy_meter
    uart_id: mercury_uart
    address: 0               # 0 = broadcast (если один счётчик)
    password: "111111"       # заводской пароль
    energy:
      name: "Меркурий — энергия"
      state_class: total_increasing
    power:
      name: "Меркурий — мощность"
    voltage:
      name: "Меркурий — напряжение"
    current:
      name: "Меркурий — ток"
    update_interval: 60s

Вариант B: RS-485 USB-адаптер → HA напрямую

Субучёт по тенантам (TenantPass)

Для биллинга — каждый арендатор имеет отдельный счётчик.

# ha_lago_bridge.py — отправка потребления в Lago каждый час
import homeassistant_client, httpx, asyncio
from datetime import datetime

async def sync_energy_to_lago():
    ha = await homeassistant_client.connect("http://ha:8123", token=HA_TOKEN)

    tenants = {
        "tenant-a": "sensor.energy_tenant_a",
        "tenant-b": "sensor.energy_tenant_b",
    }

    for tenant_id, sensor in tenants.items():
        state = await ha.get_state(sensor)
        kwh = float(state.state)

        await lago.post("/api/v1/events", json={"event": {
            "transaction_id": f"energy-{tenant_id}-{int(datetime.now().timestamp())}",
            "external_customer_id": tenant_id,
            "code": "electricity_kwh",
            "properties": {"kwh": kwh}
        }})

TenantPass — субучёт арендаторов

SDM630 (вводной, трёхфазный) — на вводе здания
SDM120 × N (субсчётчики) — на каждого арендатора
→ HA Energy Dashboard с фильтром по tenant_id
→ Lago: почасовой usage event → счёт в конце месяца

EventPass (стройплощадка)

Стройплощадка: временное подключение к электросети
PZEM-004T на каждом щитке строительном (бытовке, башенном кране)
ESP32 с 4G (нет WiFi на стройке)
→ MQTT → HA → отчёт по потреблению
→ Алерт при превышении мощности (защита от КЗ)
→ Биллинг субподрядчиков по факту потребления

Защита и алерты в HA

# automation: потребление превысило порог
- alias: "Электро: критическое потребление"
  trigger:
    - platform: numeric_state
      entity_id: sensor.power_main
      above: 9000      # Вт (при вводе 16А × 220В = 3520Вт, корректируйте)
  action:
    - service: notify.mobile_app_owner
      data:
        title: "Высокое потребление!"
        message: >
          Сейчас: {{ states('sensor.power_main') }} Вт.
          Проверьте что включено.

# automation: нет сети → ИБП / генератор
- alias: "Электро: пропало напряжение"
  trigger:
    - platform: numeric_state
      entity_id: sensor.voltage_main
      below: 180
  action:
    - service: notify.mobile_app_owner
      data:
        message: "Напряжение упало до {{ states('sensor.voltage_main') }}В"
    - service: switch.turn_off
      target:
        entity_id:
          - switch.boiler_gvs     # отключить бойлер (приоритет 4)
          - switch.warm_floor_2   # тёплый пол 2 этаж
