Роли (RBAC-основа)

РольЧто видит / может
employeeТолько свои отметки, свой табель
site_managerСотрудники своего объекта, корректировка явок (в течение 24 ч)
tenant_adminУправление пользователями своей организации-арендатора
hrТабели по компании (только чтение), без настройки терминалов
adminУправление терминалами, правилами, интеграциями
auditorТолько чтение табелей и логов

Атрибуты (ABAC-расширение)

Атрибуты субъекта

  • tenant_id — организация-арендатор
  • site_id — объект/здание
  • department — подразделение
  • employment_type — тип занятости (штат / подрядчик / гость)

Атрибуты ресурса

  • resource.type — door, elevator, workstation, timesheet
  • resource.tenant_id — кому принадлежит ресурс
  • resource.site_id — на каком объекте
  • resource.shift_end — когда закончилась смена (для табеля)

Атрибуты окружения (контекст)

  • time — рабочее / нерабочее время
  • ip / network — корпоративная сеть или нет
  • amr — метод аутентификации (fido2, nfc, password)
  • device_trusted — устройство проверено (MDM-сертификат)

Пример политик

# Менеджер видит только свой объект своего арендатора
user.role == "site_manager"
AND user.tenant_id == resource.tenant_id
AND user.site_id == resource.site_id

# Вход через дверь только в рабочее время и только по FIDO2/NFC
resource.type == "door"
AND time.in(work_hours)
AND amr contains ("fido2" OR "nfc")

# Корректировка табеля — только в течение 24 ч после смены
resource.type == "timesheet"
AND user.role == "site_manager"
AND (now - resource.shift_end) < 24h

Принципы

  • Минимум привилегий: каждая роль видит только то, что нужно
  • Запрет по умолчанию: всё, что явно не разрешено — запрещено
  • Аудит каждого решения: permit И deny записываются
  • Автономность: при недоступности Keycloak — режим по последним известным разрешениям (для дверей)
  • Централизованность: ни один терминал не принимает решение самостоятельно
