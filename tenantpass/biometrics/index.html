Биометрия, Passkeys, NFC, BLE

Биометрия, Passkeys, NFC, BLE

Принцип: Keycloak не хранит биометрию

Keycloak не хранит шаблоны и не читает биометрические данные. Он доверяет результату FIDO2/WebAuthn-аутентификации.

Приватный ключ passkey хранится на устройстве пользователя → сервер хранит только публичный ключ → под 572-ФЗ это не «биометрические данные для аутентификации» в хранилище.

Механизмы идентификации

МеханизмЧто Keycloak получаетТребования к железу
Passkey (WebAuthn/FIDO2)Криптоподтверждение биометрии без шаблонаСмартфон с passkey поддержкой
NFC-карта (FIDO2)То же, аутентификатор на картеСчитыватель NFC у двери
BLE (приближение)Атрибут «пользователь в зоне двери»BLE-считыватель + RSSI
Биометрический терминалФакт успешной идентификации (передаёт агент)Терминал с локальной проверкой

Поддержка Keycloak

  • Passkeys как supported feature с 26.0
  • Может использоваться в conditional UI и modal UI
  • amr claim в токене содержит метод аутентификации → можно проверять в ABAC-политике

Смартфон: что важно

  • BLE выключен → пользователь не обнаружится у двери
  • Нет BLE → сценарий «подошёл → открылось» не работает
  • Без MDM → нет клиентского сертификата → нет атрибута «корпоративное устройство»
  • Тип смартфона влияет на шаг сенсорного слоя, не на Keycloak

572-ФЗ и хранение биометрии

  • Внутренний СКУД предприятия: предприятие — оператор ПДн своих сотрудников. Аккредитация по 572-ФЗ не нужна. Хранение шаблонов допустимо с согласия, при шифровании.
  • Сервис аутентификации для третьих лиц: нужна аккредитация (капитал ≥ 500 млн ₽, лицензия ФСБ). Практически недоступно на старте.
  • Запрет хранения биометрии для аутентификации (ст. 15 572-ФЗ) кроме разбора обращений (≤ 10 суток).

Стратегия: использовать passkeys → приватный ключ на устройстве → сервер не хранит биометрию как таковую.
