Offline-режим СКУД (замечание 1+2)

TenantPass — устойчивость к недоступности Keycloak

Проблема

Стандартный flow СКУД: каждое поднесение карты → HTTP к Keycloak (UMA-ticket, 2–3 round-trip, ≥300 мс). При недоступности Keycloak (сбой, деплой, сеть) — весь СКУД встаёт.

Решение: двухуровневый кэш на агенте PEP

sequenceDiagram participant T as Терминал participant A as Агент PEP participant R as Redis (local) participant K as Keycloak T->>A: card_id presented A->>R: GET permit:{card_id}:{door_id} alt кэш HIT (TTL не истёк) R-->>A: {permit: true/false, cached_at} A->>T: open / deny (< 50 мс) else кэш MISS или истёк A->>K: POST /realms/.../protocol/uma/token K-->>A: RPT token (permit/deny) A->>R: SET permit:{card_id}:{door_id} TTL=300s A->>T: open / deny end note over K: Keycloak DOWN → A->>R: GET permit:{card_id}:{door_id} alt есть запись (любой TTL — stale fallback) R-->>A: stale cached permit A->>T: применить fallback-политику двери else нет записи A->>T: применить default-политику end

Redis на агенте

Каждый агент PEP запускает локальный Redis (или Redis Sentinel). Не облачный, не shared — физически рядом с контроллером.

# docker-compose.agent.yml
services:
  pep-agent:
    image: tenantpass/pep-agent:latest
    environment:
      KEYCLOAK_URL: https://kc.tenantpass.ru
      REDIS_URL: redis://localhost:6379
      CACHE_TTL_SECONDS: 300          # 5 мин — нормальный режим
      STALE_TTL_SECONDS: 3600         # 1 ч — stale fallback при offline
    depends_on:
      - redis-local

  redis-local:
    image: redis:7-alpine
    command: redis-server --save "" --maxmemory 64mb --maxmemory-policy allkeys-lru
    volumes:
      - redis_data:/data   # пережить рестарт агента

volumes:
  redis_data:

Кэш-ключи и структура

# pep/cache.py
from dataclasses import dataclass
from datetime import datetime
import json, redis

CACHE_TTL   = 300   # секунд — обычный режим
STALE_TTL   = 3600  # секунд — при offline Keycloak

@dataclass
class CachedPermit:
    card_id: str
    door_id: str
    permit: bool
    cached_at: str
    source: str   # "keycloak" | "stale"

class PermitCache:
    def __init__(self, redis_client: redis.Redis):
        self.r = redis_client

    def key(self, card_id: str, door_id: str) -> str:
        return f"permit:{card_id}:{door_id}"

    def get(self, card_id: str, door_id: str) -> CachedPermit | None:
        raw = self.r.get(self.key(card_id, door_id))
        if raw:
            return CachedPermit(**json.loads(raw))
        return None

    def set(self, card_id: str, door_id: str, permit: bool):
        data = CachedPermit(
            card_id=card_id, door_id=door_id,
            permit=permit, cached_at=datetime.utcnow().isoformat(),
            source="keycloak"
        )
        # Записываем с STALE_TTL — сам кэш живёт дольше,
        # свежесть проверяем по cached_at
        self.r.setex(self.key(card_id, door_id), STALE_TTL, json.dumps(data.__dict__))

Инвалидация кэша через Keycloak Event Listener

При деактивации сотрудника Keycloak должен немедленно уведомить всех агентов.

# keycloak-event-listener / webhook → pep agents

# Keycloak: Admin Events → Webhook extension (Keycloak Webhook SPI)
# При событии: USER_DISABLED, ROLE_REMOVED, GROUP_MEMBERSHIP_CHANGED →
# POST /agents/invalidate {"user_id": "...", "scope": "all_doors"}

# pep/invalidation.py
async def handle_invalidation(user_id: str, door_id: str | None = None):
    """Удалить все кэш-записи для пользователя (или конкретной двери)"""
    pattern = f"permit:*:{door_id}" if door_id else f"permit:*"
    keys = r.scan_iter(match=pattern)
    for key in keys:
        data = json.loads(r.get(key) or "{}")
        if data.get("card_id") == user_id or door_id is None:
            r.delete(key)

Fallback-политика по типу двери

# door-policy.yaml — конфиг агента
doors:
  entrance_main:
    fail_mode: fail_open       # эвакуационный выход
    stale_cache_allowed: true  # использовать устаревший кэш
    stale_max_age_hours: 1

  server_room:
    fail_mode: fail_closed     # серверная — только deny при offline
    stale_cache_allowed: false # никогда не использовать stale

  office_floor_1:
    fail_mode: fail_open
    stale_cache_allowed: true
    stale_max_age_hours: 4

  parking:
    fail_mode: fail_open
    stale_cache_allowed: true
    stale_max_age_hours: 8

# pep/decision.py
def make_decision(card_id: str, door: DoorConfig, cache: PermitCache) -> bool:
    cached = cache.get(card_id, door.id)

    if cached:
        age_hours = (datetime.utcnow() - datetime.fromisoformat(cached.cached_at)).total_seconds() / 3600
        if age_hours <= CACHE_TTL / 3600:
            return cached.permit   # свежий кэш — доверяем

        # stale cache
        if door.stale_cache_allowed and age_hours <= door.stale_max_age_hours:
            log.warning("Using stale cache for %s at %s (age=%.1fh)", card_id, door.id, age_hours)
            return cached.permit

    # нет кэша или stale не разрешён
    return door.fail_mode == "fail_open"

Latency бюджет

РежимВремя ответаОписание
Кэш HIT (Redis local)1–5 мсRedis на localhost, без сети
Кэш MISS → Keycloak80–300 мс1 HTTP round-trip + JWT validation
Offline (stale cache)1–5 мсFallback из Redis
Offline (no cache)1–5 мсDefault политика двери

Цель: 95-й перцентиль < 200 мс, что даёт ~5 чел/сек пропускной способности на турникет.

Pre-warming кэша

При старте агента — скачать весь список разрешений для своих дверей:

# pep/startup.py
async def warm_cache(doors: list[str], keycloak: KeycloakClient, cache: PermitCache):
    """При старте агента — загрузить разрешения для всех активных сотрудников"""
    users = await keycloak.get_active_users_with_access(resource_ids=doors)
    for user in users:
        for door_id in user.permitted_doors:
            cache.set(user.card_id, door_id, permit=True)
    log.info("Cache warmed: %d permits for %d doors", len(users), len(doors))
