Роли пользователей

Роли пользователей

Иерархия: Платформа → Арендатор → Объект → Сотрудник. Роли вышестоящего уровня не наследуют автоматически права нижестоящих — каждый уровень явно задаётся через атрибуты и политики.

Уровень платформы

platform_admin

Управляет всей платформой TenantPass. Создаёт и удаляет арендаторов, управляет глобальными настройками Keycloak.

ДоступОписание
ДанныеВсе realm’ы и организации
ФизическийНет (не операционная роль)
ОперацииCRUD арендаторов, управление realm-настройками, ротация ключей, просмотр системных логов

Ограничения: не видит персональные данные сотрудников арендаторов (принцип минимума привилегий). Доступ только из управляющего сегмента сети.

platform_auditor

Только чтение системных событий и метрик по всей платформе. Нужен для внешнего аудита (ФСТЭК, ФСБ).

ДоступОписание
ДанныеСистемные логи Keycloak, статистика по арендаторам (без ПДн)
ФизическийНет
ОперацииТолько чтение; экспорт отчётов по инцидентам

Уровень арендатора

tenant_admin

Администратор организации-арендатора. Управляет своими пользователями, объектами и правилами доступа в рамках своей организации.

ДоступОписание
ДанныеВсе данные своего арендатора (tenant_id совпадает)
ФизическийНет (административная роль)
ОперацииCRUD сотрудников, назначение ролей внутри org, создание объектов, настройка графиков

Ограничения: не видит данные других арендаторов. Не может менять глобальные политики Keycloak.

hr

Кадровый специалист арендатора. Работает с табелями, расчётом ЗП, документами сотрудников.

ДоступОписание
ДанныеТабели всех сотрудников своего арендатора; документы (медкнижки, инструктажи)
ФизическийНет
ОперацииПросмотр и экспорт табелей (Excel/1С); уведомления о просроченных документах; управление графиками

Ограничения: не может корректировать явки (только site_manager). Не видит данные других арендаторов.

security_officer

Офицер безопасности арендатора. Управляет правилами физического доступа, расследует инциденты.

ДоступОписание
ДанныеЖурналы проходов всех объектов своего арендатора; список активных сессий
ФизическийМожет удалённо заблокировать доступ сотруднику (emergency_revoke)
ОперацииПросмотр и экспорт журналов; блокировка/разблокировка пользователя; управление группами допуска

Ограничения: не может просматривать HR-данные (зарплата, медкнижки). Отзыв доступа — с обязательной записью причины в аудит.

tenant_auditor

Аудитор арендатора. Только чтение по всем данным своей организации.

ДоступОписание
ДанныеВсе журналы, табели, события доступа своего арендатора
ФизическийНет
ОперацииТолько чтение; экспорт отчётов

Уровень объекта

site_manager

Управляющий конкретным объектом (зданием, площадкой, торговой точкой). Ключевая операционная роль.

ДоступОписание
ДанныеСотрудники и журналы только своего объекта (site_id совпадает)
ФизическийВсе зоны своего объекта
ОперацииПросмотр явок в реальном времени; корректировка табеля (в течение 24 ч после смены); управление сменным расписанием; ручное открытие/блокировка двери

ABAC-политика: user.tenant_id == resource.tenant_id AND user.site_id == resource.site_id.

Ограничения: не видит другие объекты, даже у одного арендатора.

shift_supervisor

Бригадир / старший смены. Оперативный контроль смены без административных прав.

ДоступОписание
ДанныеСписок присутствующих сотрудников своей бригады в текущей смене
ФизическийРабочая зона своей бригады
ОперацииПросмотр явок в реальном времени; отметка причины отсутствия (не корректировка табеля)

Уровень сотрудника

employee

Штатный сотрудник. Базовая роль.

ДоступОписание
ДанныеТолько свои отметки, свой табель, свой профиль
ФизическийЗоны, разрешённые его должности и объекту
ОперацииПросмотр своего табеля; просмотр своего расписания; уведомления об опозданиях

Физический доступ задаётся через атрибуты site_id + access_group, а не жёстко в роли.

contractor

Подрядчик / субподрядчик. Временный доступ на объект с ограниченным сроком.

ДоступОписание
ДанныеТолько свои отметки
ФизическийТолько явно указанные зоны; только в разрешённый период (valid_from / valid_until)
ОперацииТолько отметка прихода/ухода

Атрибут valid_until — ABAC-политика автоматически блокирует доступ после истечения срока. Уведомление арендатору за 24 ч до истечения.

visitor

Посетитель. Разовый или краткосрочный доступ.

ДоступОписание
ДанныеНет
ФизическийТолько зона приёма / указанный маршрут; только сопровождении employee или site_manager (опционально)
ОперацииТолько отметка прихода/ухода на проходной

Создаётся tenant_admin или site_manager с коротким valid_until. Удаляется автоматически.

tech_staff

Технический персонал: уборка, обслуживание оборудования, IT-поддержка.

ДоступОписание
ДанныеТолько свои отметки
ФизическийТехнические зоны (access_group: technical); по расписанию или с подтверждением site_manager
ОперацииОтметка прихода/ухода; возможность открыть «сервисный доступ» с логированием

security_guard

Охранник на объекте. Мониторинг, ручное управление точками доступа.

ДоступОписание
ДанныеЖурнал проходов своего объекта в режиме реального времени
ФизическийПост охраны + возможность открыть/заблокировать любую дверь объекта вручную
ОперацииРучное открытие/блокировка точек доступа; сигнал тревоги; просмотр кто на объекте

Каждое ручное действие записывается в журнал с обязательным указанием причины.

Разделение обязанностей (SoD)

Конфликтующие пары ролей — нельзя назначить одному пользователю:

ПараПричина
hr + site_managerHR не должен корректировать табель, который сам же видит
security_officer + tenant_adminПроверяющий не должен управлять тем, что проверяет
platform_admin + platform_auditorАудитор независим от администратора
