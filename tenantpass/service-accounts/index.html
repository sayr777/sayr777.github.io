Системные пользователи (Service Accounts)

Системные пользователи (Service Accounts)

Машинные учётные записи для взаимодействия сервисов внутри системы. Не являются людьми. Не входят в пользовательский интерфейс. Аутентификация только через Client Credentials Flow.

Принципы

  • Каждый сервис имеет свой client с минимально необходимыми правами
  • Никаких shared credentials между сервисами
  • Все межсервисные вызовы идут через Keycloak token → проверяются получателем
  • Ротация client secret — по расписанию или при подозрении на компрометацию
  • Все вызовы логируются с указанием client_id источника

Список сервисных аккаунтов

door-controller-client

Кто: агент контроллера дверей и лифтов на каждом физическом устройстве.

ПараметрЗначение
Grant typeClient Credentials
Праваuma_protection — может запрашивать entitlement для своих ресурсов
Scopesdoor:enter, door:exit, elevator:use
РесурсыТолько двери/лифты своего site_id

Что делает:

POST /realms/{realm}/protocol/openid-connect/token
  grant_type=urn:ietf:params:oauth:grant-type:uma-ticket
  audience=door-controller-client
  permission=door:{door-id}#enter
  subject_token={user_token}
→ получает RPT, проверяет permit/deny, открывает замок

Ограничения: не может читать данные пользователей. Не имеет доступа к Admin API.

workstation-agent-client

Кто: агент на рабочей станции (ПК сотрудника).

ПараметрЗначение
Grant typeClient Credentials
Праваuma_protection для ресурсов типа workstation
Scopesworkstation:unlock, workstation:lock

Что делает:

При приближении пользователя (BLE):
  1. Получает user_token из корпоративного приложения
  2. Запрашивает permit на workstation:{pc-id}#unlock
  3. При permit → разблокирует сессию ОС

При уходе (BLE signal lost > 30 сек):
  1. Блокирует экран
  2. Записывает событие выхода

timetracking-service-client

Кто: сервис учёта рабочего времени — хранит события отметок, считает табель.

ПараметрЗначение
Grant typeClient Credentials
ПраваЧтение пользователей своих арендаторов (фильтр по tenant_id)
Scopesuser:read, timesheet:write, timesheet:read
Admin APIview-users в рамках своего realm

Что делает:

  • Принимает события от агентов дверей (приход/уход)
  • Считает рабочие часы, опоздания, переработки
  • Отдаёт табель hr-интерфейсу и интеграции с 1С

Ограничения: не может создавать/удалять пользователей. Не может менять роли.

notification-service-client

Кто: сервис уведомлений — email, push, SMS.

ПараметрЗначение
Grant typeClient Credentials
ПраваЧтение email и телефона пользователей для отправки
Scopesuser:read (только email, phone_number)

Что делает:

  • Получает задачи на отправку от других сервисов (через очередь)
  • Отправляет: опоздания, просроченные документы, invite-ссылки, алерты безопасности

Ограничения: получает только email и phone_number, никаких других атрибутов пользователя.

document-service-client

Кто: сервис управления документами (медкнижки, инструктажи, допуски).

ПараметрЗначение
Grant typeClient Credentials
ПраваЧтение и запись атрибутов документов пользователей
Scopesuser:read, user:update-attributes (только doc_* атрибуты)

Что делает:

  • Хранит реквизиты документов и даты истечения
  • За 7 дней до истечения → ставит задачу notification-service
  • При истечении → уведомляет access-policy-service для блокировки

access-policy-service-client

Кто: сервис управления политиками доступа — синхронизирует правила между Keycloak и агентами.

ПараметрЗначение
Grant typeClient Credentials
ПраваУправление ресурсами и политиками в Keycloak Authorization Services
Admin APImanage-authorization, view-authorization

Что делает:

  • Регистрирует новые ресурсы при добавлении дверей/объектов
  • Обновляет политики при смене правил арендатора
  • При увольнении → инициирует инвалидацию кэшей агентов

management-service-client

Кто: бэкенд панели управления (для tenant_admin и platform_admin).

ПараметрЗначение
Grant typeClient Credentials + on-behalf-of (Token Exchange)
Admin APImanage-users, manage-groups, view-users в своём realm

Что делает:

  • CRUD пользователей и организаций от лица tenant_admin
  • Передаёт identity пользователя через Token Exchange (действует «от имени»)
  • Назначает атрибуты (site_id, tenant_id, valid_until)

Token Exchange важен: когда tenant_admin создаёт сотрудника, сервис действует не под своим client_id, а «от имени» tenant_admin — это фиксируется в аудите.

1c-integration-client

Кто: интеграционный шлюз с 1С / ERP.

ПараметрЗначение
Grant typeClient Credentials
ПраваТолько чтение табелей (конкретный endpoint, конкретный tenant_id)
Scopestimesheet:read
IP whitelistТолько с IP сервера 1С

Что делает:

  • Периодически забирает закрытые табели
  • Передаёт в 1С для расчёта ЗП

Ограничения: самые жёсткие в системе — только чтение, только свой арендатор, только из белого IP.

audit-export-client

Кто: сервис экспорта журналов для аудита (ФСТЭК/ФСБ).

ПараметрЗначение
Grant typeClient Credentials
ПраваЧтение событий Keycloak Event Store
Scopesevents:read

Что делает:

  • Собирает события из Keycloak Event Store
  • Подписывает экспорт ЭП системы (для юридической значимости)
  • Доступен только platform_auditor
